## 2026-10-19 — fix(hooks): every printed mods-ok key clears its PluginDriftCheck warning

- `PluginDriftCheck.hook.ts` (#648): an id that `shown()` cannot print unchanged (unsafe characters, or over 300 characters) was marked "cannot be allowlisted", so the warning's `# mods-ok: <id>` remediation could never clear it. Such an id is now printed sanitized alongside the key `sha256:<first 16 hex of the SHA-256 of the raw id's UTF-16LE code units>`, and that key is its only allowlist match; a verbatim id is still its own key. The hash reads UTF-16 code units, not UTF-8, because UTF-8 encoding maps every lone surrogate to U+FFFD and would give distinct ids one key. The token contains `:`, which no verbatim id can, so a raw id cannot spell out another id's token. Output stays sanitized and length-bounded. A project `.claude/skills` mod, which the allowlist never covers, is marked `(sanitized)` with no key.
- `plugin-drift.test.sh`: the key the warning prints for an unsafe id is captured from the output and proven to clear it; a sha256 token does not cover a verbatim id; two names differing only in a lone surrogate get distinct keys; the existing >100-character safe id stays printed whole and allowlistable.
- Allowlist syntax documented in the hook header, `CLAUDE-GUIDE.md` (Hooks table) and `claude/plugins.txt`.
