## 2026-10-20 — fix(hooks): PluginDriftCheck rescans mid-session and resolves plugin paths like the loader

- `PluginDriftCheck.hook.ts` (#618): the hook is now also registered on `UserPromptSubmit`. Its cheap path reads this session's state file at `~/.local/state/plugin-drift/SESSION_ID` and stats every path the last full scan read or listed, about 506 on the operator's machine. The file is plain text and ends in an `end` line, so a truncated file reads as damaged. The cheap path parses no JSON and runs no subprocess. A full rescan runs only when a size, mtime, inode or existence changed (a dangling symlink is signed by `lstat`), or when `CLAUDE_CODE_PLUGIN_DIRS`, `CLAUDE_CONFIG_DIR` or `CLAUDE_CODE_PLUGIN_CACHE_DIR` changed. It then names only the mods and unverifiable plugins this session has not been told about yet. A missing or damaged state file counts as a change. Paths and labels are stored as hex-encoded UTF-16 code units, which handles a lone surrogate. SessionStart prunes state files older than 30 days. Measured on the operator's machine: about 33 ms for the cheap path, against a bun startup floor of about 40 ms; about 57 ms for a full scan at SessionStart; about 47 ms for a rescan after a change.
- `PluginDriftCheck.hook.ts` (#647, partial): paths resolve as Claude Code resolves them.
  - Every `~/.claude` path is read under `CLAUDE_CONFIG_DIR` (https://code.claude.com/docs/en/claude-directory).
  - `CLAUDE_CODE_PLUGIN_CACHE_DIR` moves the plugins root: registry, marketplaces and cache (https://code.claude.com/docs/en/env-vars). claude.ai synced plugins stay under the config dir, which was checked against the CLI.
  - Each absolute or `~`-prefixed `CLAUDE_CODE_PLUGIN_DIRS` entry is scanned as `NAME@inline`. A relative entry is skipped, as the loader skips it, and an archive is reported as unverifiable.
  - Loader-differential cases stay best-effort: Claude Code exposes no list of loaded hook modules. A `claude plugin list --json` union was tried and dropped, because it lists no modules and cost about 900 ms per scan.
  - An upstream feature request is drafted for the operator to file.
- `check-hooks-wired.sh`: new `EVENT_WIRING` check. It requires `PluginDriftCheck.hook.ts` on both `SessionStart` (install drift and the full scan) and `UserPromptSubmit` (the rescan). The operator still has to add the `UserPromptSubmit` registration to the private `settings.json`.
- `CLAUDE-GUIDE.md` (Hooks): documents the rescan and the path resolution, and says why the mod scan is best-effort.
- `plugin-drift.test.sh`: a stub `claude` on PATH proves the hook never runs the CLI. New cases cover the config dir, the moved plugins root, `~` and relative plugin-dir entries, and the mid-session rescan. The rescan cases are: a mod installed or edited in place, a dangling `hooks.json`, no repeated reports, per-session state, damaged and truncated state, a cwd change, a changed loader variable, a project skills link replaced by a directory, an unsafe session id, and pruning.
